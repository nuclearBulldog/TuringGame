# Themed Pixel-Art Pipeline & Battle/Overworld Polish — Design

**Date:** 2026-07-24
**Status:** Approved design direction (art = themed concept sprites; backdrop = campus/classroom)

## Goal

Replace the procedurally-drawn generic figures (player, enemies, battle creatures)
with a sheet-driven pixel-art pipeline, and polish the battle + overworld UI so the
game reads as an AI-ethics game. Real art must later be a **pure PNG file-swap** — no
code edits.

## Findings

- The five "unused" PNGs are **not** clean sprite grids and hold **no character art**:
  - `hero.png` (192×64) is a *"TURING GAME" logo*.
  - `battle-sheet.png` (480×224) and `ui_sheet.png` (256×256) are loose UI/design
    mockups (blue-framed panels, PLAY/QUIT buttons, HP strips).
  - `hp.png` (128×16) is a small ambiguous bar strip.
- Their **blue-frame / gray-panel style + the `dawnbringer-32.pal` palette** are the art
  direction to match; the sprites themselves must be generated fresh on a uniform grid.
- `AnimationController` is already sheet-agnostic: it consumes `{state: [Surface,…]}` +
  `fps_by_state`. The loader's only job is producing that dict. **No controller changes.**
- Enemies carry `encounter_id`; `BattleSystem` is built from the encounter. A new
  `"sprite"` field in `encounters.json` is the single source of truth for both the
  overworld enemy sprite and the battle creature.
- Tests run headless (`SDL_VIDEODRIVER=dummy`) with a dummy display set, so
  `.convert_alpha()` works — the loader still guards on `pygame.display.get_surface()`.
- Baseline: **115 tests pass, ruff clean.**

## Components

### 1. `systems/spritesheet.py` (new, headless-safe)
- `load_sheet(path)` → `Surface`; calls `.convert_alpha()` only when a display surface
  exists, else returns the raw loaded surface.
- `slice_grid(sheet, frame_w, frame_h)` → `list[Surface]` (row-major, `.copy()`d).
- `load_states(path, frame_w, frame_h, layout)` → `{state: [Surface,…]}` where `layout`
  maps a state to `(row, start_col, count)`. Keys chosen by the caller so they match
  `AnimationController` exactly.

### 2. Asset manifest (generated by Gemini with pygame; frozen in `assets/README.md`)

| Asset | Frame | Grid | Sheet px | Rows / states |
|---|---|---|---|---|
| `player.png` | 32×48 | 4×3 | 128×144 | row0 idle(2), row1 run(4), row2 jump(1) |
| `enemies.png` | 32×44 | 4×5 | 128×220 | one row per sprite key; idle=cols 0–1, run=cols 0–3 |
| `battle_bg.png` | — | single | 960×580 | campus/classroom backdrop |
| `hp.png` | — | single | 132×16 | bar frame (border + empty track); fill drawn in-code |

**Enemy row order (sprite keys):** `report_due, deepfake_classmate, hiring_filter,
exam_proctor, study_bot`. Placeholder style = **themed concept sprites** (each enemy
evokes its scenario in palette colours; player = a simple student figure).

### 3. Sprite wiring
- `encounters.json`: add `"sprite": "<key>"` per encounter.
- `Enemy.__init__` takes/derives a `sprite_key` (default `report_due`); `BattleSystem`
  exposes `self.sprite_key` (read from encounter, safe default). **No battle-logic change.**
- `Player._build_animations()` / `Enemy._build_animations()` call `load_states(...)`
  instead of drawing primitives, returning the same `{idle,run(,jump)}` dicts.

### 4. Battle scene (`ui/battle_ui.py`)
- `draw_creature()` blits a sprite (reuse `player.png` / `enemies.png` idle frame scaled
  up to the current ~96px creature box) instead of the ellipse blob.
- `_draw_background()` blits `battle_bg.png` instead of the flat green fill.
- **Damage feedback:** `BattleUI` tracks last-seen `player_hp`/`enemy_hp` via `getattr`
  (defensive, so `MockBattleSystem` without HP attrs stays safe); a drop starts a
  hit-flash (white tint) + shake (few-frame positional jitter) timer, advanced by a new
  `BattleUI.update(dt, system)` called from `BattleState.update` (state file, not logic).

### 5. UI/UX polish
- HP bars blit the `hp.png` frame + a palette-coloured fill rect in the track.
- Dialogue frame + move buttons: clearer selected state (highlight + inset), readable
  framing, all colours via **new `settings.py` constants sourced from `dawnbringer-32`**.
  No raw RGB literals in any draw code I touch.

## Constraints / guard rails
- Do NOT modify `AnimationController`'s public API or `battle_system.py` logic.
- No new dependencies (placeholders made with pygame, not PIL).
- Keep `WIDTH=960 / HEIGHT=580`.
- `tests/ui/test_button.py` and `tests/states/test_battle.py` must keep passing.
